# Retrieval Module — Technical Documentation

## 1. Purpose

The retrieval module is responsible for efficiently retrieving recipes based on user queries. It utilizes the embeddings generated by the embeddings module to find the most relevant recipes through similarity search.

**What it does end-to-end:**

1. Loads the pre-computed embeddings and associated metadata.
2. Encodes user queries into the same vector space as the recipe embeddings.
3. Performs a nearest-neighbor search using cosine similarity to find the most similar recipes.
4. Maps the results back to the original recipe details for user display.

## 3. How the Retrieval Process Works

The retrieval process involves several key steps:

### 3.1 Loading Artifacts

The module loads the necessary artifacts, including the embeddings and recipe metadata, to facilitate efficient querying.

### 3.2 Query Encoding and Cosine Similarity

User queries are encoded into the same vector space as the recipe embeddings using the same model employed in the embeddings module.

The query and recipe embeddings are transformed into an array and put into a cosine-similarity function as defined in `src/recipe_discovery/retrieval/similarity.py`, to generate a cosine similarity score out of it. Cosine similarity is employed in this scenario in order to ensure that the user's most optimal recipe is defined by the similarity of the vectors irrespective to its magnitude. This will prevent the model from putting biases on recipes where there is a strong magnitude in length. 

### 3.3 Ranking and Filtering Dataset

After finding the scores for the cosine similarity, the scores are then sorted from greatest to least and merged with the processed CSV through `src/recipe_discovery/retrieval/ranker.py`. 

The merged CSV will then go through a filtering system as defined by `src/recipe_discovery/retrieval/filters.py` to only optimize on factors that are clearly defined by the user and can be easily filtered by the model. This would include factors like dietary restrictions, number of ingreidents or time needed. 

We would then filter and only keep the recipes based on those that are deemed appropiate. 

### 3.3 Nearest Neighbor Search


The module utilizes a nearest neighbor search algorithm to find the top-k most similar recipes based on cosine similarity. We do this by using the already ranked dataset and pick the top 10 recipes.

## 4. Cosine Similarity

When a user inputs a query, the system processes it as follows:

Cosine similarity is a metric used to measure how similar two vectors are, regardless of their magnitude. It is defined as the cosine of the angle between two non-zero vectors in an inner product space. The cosine similarity is calculated using the following formula:

\[
\text{cosine\_similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|}
\]

Where:
- \( A \cdot B \) is the dot product of the vectors \( A \) and \( B \).
- \( \|A\| \) is the magnitude (or length) of vector \( A \).
- \( \|B\| \) is the magnitude (or length) of vector \( B \).

The result of the cosine similarity ranges from -1 to 1:
- A cosine similarity of 1 indicates that the two vectors are identical in direction.
- A cosine similarity of 0 indicates that the two vectors are orthogonal (i.e., they have no similarity).
- A cosine similarity of -1 indicates that the two vectors are diametrically opposed.

In the context of the retrieval module, cosine similarity is used to determine how closely related a user query is to the recipe embeddings, allowing the system to recommend the most relevant recipes based on the user's input. In our alogrithm, we take in the input of the query and the processed CSV in the form of a processed array. We then convert it and normalize it through linear algebra. Then we use the equation above to produce the cosine similarity value. 

Our Cosine Similarity Algorithm:

```yaml

def cosine_similarity(query: np.ndarray, matrix: np.ndarray) -> np.ndarray:
    """Return cosine similarity scores between one query vector and a matrix."""
    query_norm = np.linalg.norm(query) + 1e-12
    matrix_norm = np.linalg.norm(matrix, axis=1) + 1e-12
    return (matrix @ query) / (matrix_norm * query_norm)

```


## 5. Filtering Layer
The basic filters that can implemented here are number of ingredients, time required and dietary restrictions. We can easily take these values and perform basic filters in the dataset. 

We take in number of ingredients as a filter type because it is possible for users to ask a query of "what are some dishes that only require x amount of ingreidents". In this case, we filter the dataframe based on the 'n_ingredients' column. Because one of the existing vectors also contain a '5-ingredients-or-less' column, we can also use that to filter out should the user request for recipes that contain less than 5 ingreidents. 

We take in dietary restrictions as a filter because this is an important aspect to one's satisfcation and safety in consuming the meal. The existing one hot vectors that concern dietary restrictions include 'vegan', 'vegetarian', 'nut-free' and more. We can use these one hot vectors to only filter the recipes that satisfy this category. We can also take in queries upon the nutritional information and filter the dataframe based on the different nutritional values. 

We take in the time required because often times, users want something fixed. While we can take in the user's query and filter it through the 'minutes' column. One-hot vectors of 'xx-minutes-or-less' exist for 15, 30, 60 minutes and one hour. We can use these to filter the recipes so it satifies the criterion given as well.

## 7. Utilizing Artifacts for K-Means Clustering

The artifacts generated from the retrieval module can significantly enhance the K-Means clustering process for recipe recommendations. Here's how:

1. **Recipe Embeddings**: The `recipe_embeddings.npy` file contains dense vector representations of recipes. These embeddings can be directly used as input for K-Means clustering, allowing the algorithm to group similar recipes based on their features.

2. **Metadata for Interpretation**: The `embedding_metadata.json` file provides essential information about the embeddings, such as the model used and the dimensions of the vectors. This metadata can help in understanding the context of the clusters formed.

3. **Recipe Texts**: The `recipe_texts.csv` file contains the canonical text for each recipe. After clustering, this text can be used to interpret and label the clusters, making it easier for users to understand the characteristics of each group.

4. **Index for Efficient Retrieval**: The `recipe_index.joblib` file, which contains a fitted `NearestNeighbors` model, can be utilized to quickly find the nearest recipes to the centroids of the clusters formed by K-Means. This allows for efficient retrieval of recipes that are representative of each cluster.

5. **Scoring for Ranking**: The `train_regression.py` file, which includes scores for recipes, can be integrated into the clustering process to prioritize recipes based on user preferences. This scoring can influence which recipes are included in each cluster, ensuring that the most relevant recipes are grouped together.

By leveraging these artifacts, the K-Means clustering process can be more effective, leading to better recipe recommendations that align with user preferences and dietary restrictions.
